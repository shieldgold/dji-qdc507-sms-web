# QDC507 独立 C 版 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development or superpowers:executing-plans to implement this plan task-by-task. Independent contract/dependency investigations use dispatching-parallel-agents; production files have one owner and shared interfaces are frozen by root.

**Goal:** 实现功能完整、接口和持久化格式兼容的独立 C 版短信管理后端，保留现有 Go 版与原生前端；仅电脑/隔离 ARM 验证，不上传或修改模块。

**Architecture:** `native-c/` 提供独立源码、构建、测试及可执行文件。C11/POSIX、yyjson、Mbed TLS、nghttp2；一个串行 AT 事务通道，业务状态各自加锁，HTTP最多8连接，后台轮询频率与Go一致。所有发送/解锁/拨号在持久化保护完成后执行，未知提交结果保持uncertain，不重试消耗SIM机会。

**Tech Stack:** 已验证的 ARMv7 soft-float GCC10.2.1 / patched musl1.2.6；Go1.23.12仅作为对照Oracle；Mbed TLS3.6.7 / nghttp2 1.71.0 / yyjson0.13.0固定源码及SHA；macOS ASan/UBSan、Linux随机源故障单测、ARM/Linux3.18.44合成PTY与私有TLS/HTTP2对端。

## 跨模块规则

共享`qdc.h`由root维护。body/key等按显式长度保存；不可用strlen截断合法NUL。JSON文档和响应的所有权写在API上，操作失败不得留下悬垂引用。后台先获取领域快照再取推送锁；不在持有推送锁时请求AT；AT事务互斥不能被状态轮询插入CMGS提交过程。`action_mu`串行用户动作，`op_mu`保护短信/新鲜SIM等组合事务，各持久化组件的锁不交叉反向持有。
