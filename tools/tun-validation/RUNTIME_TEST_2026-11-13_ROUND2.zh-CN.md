## USB 中止定位

未加载 TUN 时，在同一 IOKit 实现中向正在读取的**电脑端线程**定向发送 SIGURG，三次均复现 `0xe00002eb`；仅在同步调用期间暂缓 SIGURG，三次均通过。修复后回归程序无需额外屏蔽也全部通过。防护限于当前 C 线程的 ReadPipeTO/WritePipeTO，返回前恢复原掩码，不屏蔽终止信号，不忽略 abort，不自动重试远端命令。

Apple 接口说明与 Go 信号实现、对照方法和结果详见 [USB 专项记录](USB_LOG_CHANNEL.zh-CN.md)。首轮没有信号记录，故仍不宣称已证明当时具体的信号来源。已排查并修复的是一条可重复触发、与首轮错误一致的主机缺陷。

修复控制器的 SHA-256 为 `6257b6564a7b65b2790267776c8c44e89c4f59506ec31386c49b86a54b6de414`，对应源码提交 `8e8e805`。本轮启用独立 USB 元数据日志，所有传输记录逐条落盘；没有停止电脑上原已运行、但未列出设备的系统 adb 服务。

## TUN 实测结果

每个动作都在独立日志 READY/GO 门控后执行；不自动串联重试。本轮只有一次加载和一次普通卸载。

| 主机时间 | 阶段 | 证据与结果 |
| --- | --- | --- |
| 19:27:57–19:28:27 | S1 加载 | insmod 状态 0，捕获 TUN 初始化消息，30 秒观察完整结束 |
| 19:28:39 | 加载回读 | tun 为 Live；内核报告 size 14,553；引用 0、holders 为空；misc/sysfs 为 `10:200`；主网络没有新接口 |
| 19:28:42–19:28:45 | S2 打开和查询 | 私有 RAM 字符节点 root/0600；TUNGETFEATURES 返回 `0x7103`；关闭正常 |
| 19:28:54–19:29:01 | S3 创建和删除 | unshare 后 netns inode 不同；仅私有命名空间出现 qdcvt0 和 lo；单队列、非持久、MTU 1500；关闭后接口消失 |
| 19:29:19–19:29:25 | S4 双向收发 | 新私有 netns 内 10 组内容逐一匹配；无超时、无意外包；关闭后接口消失 |

S4 使用文档地址 192.0.2.1/192.0.2.2、UDP 39000/39001，不连接外部 VPN，不设置默认路由或 veth。每组先从 UDP socket 发送，在 TUN FD 读出并校验，再构造反向 IPv4/UDP 包写入 TUN，由 UDP socket 接收并校验。每组双向负载均为 29 字节，含运行 ID、方向和序号。

最终 qdcvt0 的 **RX/TX 各为 10 包、570 字节**，错误和丢弃均为 0；`TRAFFIC_OK pairs=10 observed_bytes=570 unrelated=0`。两次生命周期均明确输出 `INTERFACE_REMOVED`，而非仅根据进程结束推定接口已删除。

实际新增 kmsg 记录为连续序号 759–769。创建/关闭时出现厂商 RMNET 的 `Kernel is trying to unregister qdcvt0/lo` 通知；候选源码 `net/rmnet_data/rmnet_data_config.c` 的注销回调会对 NETDEV_UNREGISTER 与 FINAL 事件输出这条 LOGH，后续读取及清理均正常。保留这些 severity 3 原文，不将其遗漏，也不把正常注销通知误当成 Oops。未发现新增 WARNING、BUG、Oops、OOM 或日志序号缺口。

## 清理、恢复与差异说明

正常卸载后，tun 模块、misc、sysfs 及系统自动创建的 `/dev/net/tun` 消失；删除私有字符节点和本轮新建的空 `/dev/net` 目录。恢复短信网页时，清理命令对 `/proc/3699/task/3699/children` 的可选读取失败，返回 1：该内核没有这个接口。此时原监管已收到 CONT，驱动和节点已清理。

随后单独核对 PID/starttime，取消本轮兜底进程，确认其消失及原监管恢复。没有重发 insmod/rmmod，也没有以这一项查询失败改变内核设置。最终扫描未发现本轮探针进程或兜底进程组残留。短信网页新进程由原监管启动，两次 HTTP 健康检查返回 200；没有主动发送短信或呼叫。

恢复后又完成 30 秒 kmsg 观察，随后删除两个 RAM 文件和私有目录，再进行约 30 秒内存/内核回读。19:33:01 最后验收确认：

- 主网络地址、MTU、配置路由、防火墙规则及 DNS 摘要与基线一致。基线 IPv6 转储中两条 `ff02::fb ... cache` 动态记录已消失，保留为缓存快照差异，不声称原始路由输出逐字相同。
- 原语音模块、内核配置摘要、boot_id 和 taint 均未变；设备没有重启或重新枚举。
- 模块、节点、临时目录/文件、探针及恢复进程均无残留；原监管与 smsweb 正常运行。
- 主机控制器于 19:33:07 正常关闭，没有留下自动重连或自动加载程序。

修复控制器在上述全过程共记录 **2,762 次传输，错误 0**；其中 591 次为空闲轮询的正常 0 字节读取，不属于丢包。主机全部阶段有完整结束状态；唯一非零的管理命令及后续修复已如上保留。
