# 短信与 VPN 共存：内存优化和验证

本轮在独立分支优化短信服务，保留现有收发、PDU 分片、SIM/PIN、认证、推送、通话控制、备份恢复及轮询行为。没有减少 charon 的 16 个工作线程、删除密码算法或插件，也没有改变内存停止条件。电脑与隔离 ARM 实验已证明主要分配热点可消除；真实模块仍运行原程序，实机临时替换尚待存储和现场恢复条件满足。

## 优化与功能边界

| 路径 | 修改 | 保持的行为 |
|---|---|---|
| AT 读取 | 去掉每字节字符串转换；线性识别无换行提示符；完整长行交付后释放过大的 scratch；显式关闭时退出 reader | CR/LF、提示符、URC、完整 PDU、长行无截断 |
| 串口重试 | 保留 O_NONBLOCK，让 Go poller 等待；初始 AT/ATE0 失败关闭端口 | 正常握手继续；SMS 初始化/PIN 错误保留端口供解锁；避免失败重试留下阻塞读取 |
| HTTP | 每连接读写缓冲各 512 B；长头按需扩容；静态资源直接使用嵌入字节 | 8 个连接、4096 B 行、8192 B 头、32 KiB 普通正文、1 MiB 恢复正文等原有限制；Cookie/错误/大响应完整性 |
| 推送 | 关闭时不创建快照；启用时仅复制 key/方向；无变化时避免 JSON 往返；哈希只分配结果字符串 | 原轮询频率、历史基线、重复事件/队列满重试、跨 SIM 隔离、来电不确定状态、原子落盘和失败回滚；变化时保留原持久化期限语义 |
| PDU | GSM7 直接打包，分片单次扫描，接收使用 Builder | 与冻结旧算法逐字节差分；完整字符表、扩展字符/ESC、UDH、10 片边界；UCS2、时区、消息 key 和验证码行为不变 |
| 构建 | 固定兼容 Go、隔离持久 Go 环境、禁止自动下载；4 KiB ELF 布局；关闭 VCS 注入以便复现 | ARMv7、CGO0、原加密及功能；64 KiB 布局可显式保留作对照 |

4 KiB 布局符合模块新鲜只读采集的 KernelPageSize。它减少文件填充，不能把文件缩小量直接当作 RSS 节省。

## 同工具链的分配对照

同一台电脑、Go 1.23.12、同一合成输入。以下是 B/op 和 allocs/op，表示分配流量，不等于常驻内存或泄漏；不是 ARM 性能预测。

| 场景 | 原版 | 优化版 |
|---|---:|---:|
| AT 256 字符行 | 34625 B / 226 次 | 256–257 B / 1 次 |
| HTTP status | 21298 B / 17 次 | 1736 B / 14 次 |
| HTTP 首页 | 33577 B / 17 次 | 1704 B / 12 次 |
| HTTP app.js | 48568 B / 17 次 | 1704 B / 12 次 |
| 300 条短信、推送关闭的真实观察循环 | 65144 B / 303 次 | 0 B / 0 次 |
| 300 条短信、推送开启且无变化 | 212000 B / 2127 次 | 约 39928 B / 305 次 |
| GSM7 1530 字符、10 片发送 | 3435109 B / 14725 次 | 约 23004 B / 183 次 |
| UCS2 670 字符 | 约 102595 B / 1532 次 | 基本不变，保留旧算法 |

HTTP 的每连接固定缓冲从 20 KiB 降到 1 KiB；8 个连接对应 160→8 KiB，不包含请求正文和按需长头。GSM7 10 片分配字节约下降 99.33%。

## 完整 ARM 应用对照

使用实际部署副本作为 before，未用 Git 重建版冒充同一个二进制。before 为 6226072 B，SHA-256 `f34cf22966012f5d88acae5aba978694674ba851124990bf85ce1ed5e05e14e7`。源码基线为 `138c1c43b20eeaa3b74c4212e89b3d4816876616`；工作分支还保留了与模块静态资源一致的“小电波”显示文字。

固定 Linux 3.18.44、48 MiB ARM guest、一个 CPU、GOMAXPROCS=1、GOGC=20、12 MiB Go 软目标、3 秒轮询和密封 PTY/HTTP 夹具。运行完整短信程序，覆盖登录、Cookie、合成 PIN 解锁、长短信接收、合成 CMGS 发送和请求 ID 去重、64 次静态资源访问、2 MiB 压力及释放。HTTP 验证 Content-Length 和完整正文，不能用截断响应得到较低 RSS。

最终 v4 两种配置均完成正常两轮、PIN 一轮、完整 charon 组合一轮。公平比较固定同一个旧 guard，以隔离应用变量：

| 指标 | 原部署 f34 | 标准 balanced | 内存 memory |
|---|---:|---:|---:|
| 二进制字节数 | 6226072 | 6135960 | 5550232 |
| HTTP 后完整 smaps RSS 均值 KiB | 7640 | 6676 | 6268 |
| HTTP 后 RSS 范围 KiB | 7528–7752 | 6676–6676 | 6236–6300 |
| 压力释放后 RSS 均值 KiB | 7648 | 6704 | 6300 |
| 组合短信采样峰值 KiB | 7472 | 6672 | 6356 |

标准版 HTTP 后 RSS 少 **964 KiB（约 12.6%）**；内存版少 **1372 KiB（约 18.0%）**，比标准版再少 408 KiB。内存版使用显式 `QDC_BUILD_PROFILE=memory` 关闭内联，保留同一功能源码；标准配置仍是构建默认。两版都保留，不把性能取舍隐藏在默认选项里。

内存版的代价是更多函数调用：同机 Go 1.23.12 微基准，HTTP status 约 0.560→0.802 微秒，GSM7 10 片构建约 65.3→121.8 微秒，启用的 300 条推送观察约 48.0→60.5 微秒；分配量基本相同。该 GSM7 构建仍远低于优化前约 1.78 毫秒，但电脑 CPU 数据不代表模块速度。两种配置的 ARM 组合分别在 30.102 / 30.012 秒内完成 10 组加密 ICMP＋本地短信 HTTP、13 次轮询、1 次合成提交及去重，均满足原期限及恢复条件。

内存候选又与最终新 guard 完成单独集成：**30.038 秒、10 组全部通过**，短信采样峰值 6216 KiB、charon 1740 KiB、CLI 844 KiB；时钟先恢复、原监管继续、VPN 退出与地址/路由清理通过。它不是与旧 guard 同条件的额外性能对照，不把这次更低采样值当成 guard 带来的确定节省量。

关闭内联使文件少 572 KiB，实际 RSS 对照约少 408 KiB；映射审视同时观察到文本及只读元数据页减少。两者不等量，也不能直接推断 NAND 实机的系统可用内存。下一轮临时测试选内存候选，标准版保留作回退和对照。

最终源码已通过全仓 race、vet、两种配置的单测和原生 Linux PTY 回归。同一 ARM/Linux 3.18.44 PTY 用例复现旧 v3 的 Close/Setup 卡住，v4 两项通过，同时验证内核 FD 已 EBADF、reader 退出。最终 `build.sh` 又分别重建两版，SHA 与已验收 ARM 二进制逐字相同：

- balanced：`1b7da731639e28fbe3b49f7ee7fb23f374bef92697400ba03870163155168103`
- memory：`805aa0ef15099af06568cf1cb18fd4e8062c8df16a517766005e3272da6dce8f`

## 恢复工具与拒绝路径

时钟 guard 修复“clock_settime 失败仍 CONT”路径；失败立即退出。仅 `resume-clock` 增加 SIGUSR1：恢复时钟、重验监管身份后输出 DELEGATED，把 CONT 决策交给挂载恢复工具；原 TERM/TTL 路径保持不变。

- 最终 guard 99692 B，SHA-256 `eb5664016154d69caf5c35f26443468fbe916d6fe9d49181f2c3d5fec7566763`。
- 原验证器正式发布 schema2 收据；同一 canonical out 的 20 项运行时、7 项共存全部通过。另 3 项真实 ARM capability/时钟案例覆盖失败、委托成功和委托失败；旧二进制实际 RED，未用假身份或 LD_PRELOAD 替代。
- swap helper 74844 B，SHA-256 `a4fdb3dfd374c67a29a5856184364681abbe4dd9c5587078e2e022a467e60f17`。保留原 fd、source inode、mount ID；固定挂载引用，普通卸载后及等待时钟结束后重验原路径，才能 CONT。
- 复制具备 90 秒单调期限、可中断 stdin poll；开始及每 64 KiB 同步前后检查 6144 KiB 下限。真实 90.198 秒到期、保持 stdin 打开时 TERM、6143 KiB 注入、存储不足、目录替换等均验证拒绝，且只清理自己的部分副本。
- 六项 ARM swap 场景通过；另用真实最终 guard 与 helper 验证 USR1→时钟恢复→DELEGATED，以及已有 SENT→原程序恢复，两项集成通过。使用合成短信进程，仅恢复 guest 时钟，不修改宿主时钟。

恢复日志要求精确身份、原文件重现和有效时钟证明；未知挂载或身份保留现场，不强卸载、不批量杀进程。断电和 SIGKILL 不能由用户态拦截，仍须有当轮现场恢复条件。

## 实机边界及下一步

本轮 USB 只读检查中，现用程序、启动脚本和直接回退版本哈希未变。另两份历史程序已只读备份到电脑并核对读取前后哈希，设备上的原文件仍在。当前 UBIFS 可用约 2744 KiB，不满足完整候选加 1 MiB 的复制门槛；同卷其他挂载路径不能增加容量。详见[存储复核](STORAGE_REVIEW_2026-11-15.zh-CN.md)及[不可执行审阅卡](swap/DEVICE_CARD.review.txt)。

新的 VPN 和短信审阅包已在电脑生成，均未绑定、禁止执行；VPN 默认 12288 KiB 准入，没有沿用此前单轮的 11776 KiB 例外。执行前仍需明确确认历史副本外移范围、当轮现场供电恢复及准入例外，并重新采集设备身份，详见[实机审阅方案](TEMP_TEST_REVIEW.zh-CN.md)。运行时仍为暂存后至少 8192 KiB、绝对不少于 6144 KiB、较原 guard 基线下降不超过 3072 KiB、30 秒/10 组、80+3 秒期限、300 秒独立恢复、180 秒守护启动年龄及日志异常即停。guard 基线继续在暂存完成、短信暂停、LOGGER_READY/GO 前采集，不改到优化短信启动之后。

通用 VM 与模块的驱动、页缓存、固件、NAND 文件映射和业务历史不同。采样峰值不是连续绝对峰值；Go 软目标不是 RSS 硬上限。加密 ICMP 走 VPN，本地短信 HTTP 不走 VPN。没有发送真实短信、拨号或完成本轮实际 APNs/语音端到端验收；不据此宣称真实模块已成功共存或适合长期无人值守运行。

源码、单测和工具纳入 Git。真实证书/私钥、设备备份、可执行文件及原始日志只保留在电脑私有目录；构建快照和摘要用于复核，不把装配 metadata 当成新的测试通过记录。
