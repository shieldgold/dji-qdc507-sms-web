# QDC507 临时专用证书连接操作约束

此流程只针对已授权的 RAM 临时验证。它基于既有 [实机准备方案](TEMP_RUNTIME_TEST_PLAN.zh-CN.md)，增加专用证书、单目标加密收发与临时时钟恢复。已完成的现场记录见 [2026-11-14 报告](REAL_VPN_TEST_2026-11-14.zh-CN.md)。请求卡仅用于逐项审阅执行，不能批量自动运行。

## 电脑准备

1. 取得新运行 ID、原始 USB 身份和现场完整断电恢复条件。复查设备、内核配置哈希、root/`/run` 挂载、短信 HTTP、原监管及子进程 PID/start tick/参数、内存、端口、地址/路由/DNS/防火墙。不得沿用历史 PID。
2. 服务器侧使用专用短期证书和独立 `/32`，只开放一个隧道内 ICMP 目标。验证实际 peer 的 `local-address`；UDP 中继必须访问这个入口，不能自动用 LAN 管理地址替代。证书服务器 ID 和实际 UDP 目的地址分别核验。
3. 本地将 `client.key`、`client.pem`、`ca.pem` 放入新建的 `0700` 目录，文件 `0600`。校验签发链、有效期、指纹和公私钥对应。保护文件不入 Git，不输出私钥或口令。
4. 准备公开 JSON 参数 `relay`、`server_id`、`client_id`、`target`、`vip`；只允许确定的 IPv4 和简单证书 ID。`prepare_connect.py` 自动拒绝配置注入和宽松的凭据权限。
5. 编译监督器并通过 CPU 测试、20 项 ARM 监督器回归、双 ARM VM 的证书/VIP/两组收发/重协商/退出清理，以及主机 UDP 中继边界测试。核对 VM 和准备包中的监督器哈希一致。实验 VM 没有 USB 或公网。
6. 运行 `runtime/prepare_connect.py --help`，按明确的本地路径生成全新受保护包；生成器只写电脑文件。它不执行 USB、客户端或路由操作。

## 日志、内存和短信暂停

使用既有受限 USB 控制器，MTU 1500、单通道、逐张卡。证据先持久写入电脑后才确认日志就绪；USB 出错即停止，不自动重连或重放变更。先上传小型监督器及紧凑采集器、自检并完成三轮 30 秒连续采集；此时短信仍正常运行。

若需要暂停短信，必须已有该项授权；暂停前先启动独立恢复守护：

```text
qdc-ike-guard resume-clock SUP_PID SUP_START 300
```

它应脱离 USB 会话的 HUP，输入 `/dev/null`，日志仅写入本轮 RAM 目录。核对 `RESUME_GUARD_READY ... restore_clock=1`、守护自身 PID/start/exe，以及原监管和短信子进程身份后，才 STOP 原监管、TERM 其原短信子进程。不得修改启动文件。记录暂停起点，240 秒内结束测试并恢复，留下守护 300 秒上限的余量。

三次间隔 5 秒的 `MemAvailable` 均须不低于 12288 KiB 才上传客户端；分片合并前不低于 8192 KiB。每个文件核对分片及完整哈希，合并后立即删除分片。模块路径仅为确认可执行的 `/run` tmpfs，不使用 `/data` 或未核实的 `/tmp`。

## 一次有界连接

1. 在日志 `LOGGER_READY` 确认后普通加载 `tun.ko`，采集 10 秒，核对注册 `10:200` 和节点；拒绝已有 `ipsec0`、VIP、目标已有具体路由、现有 UDP 500/4500 或 `/run/qdc-ike`。
2. 在 Mac 启动 `runtime/udp_relay.py`，仅绑定本机 USB IPv4 的 45000 端口，并使用 `--server` 明确指定企业 peer 的实际入口。它只接受模块 4500 源端口，后端只连接指定服务器 500/4500，最多 8192 字节、运行不超过 300 秒；不改 Mac 路由或防火墙。初始 keepalive 的端口未就绪错误属于单独记录的预热阶段。
3. 核实恢复守护仍在、短信监管仍停止，再把模块的**运行时系统时间**临时设为主机可信当前时间；不写 RTC、校时服务或启动配置。持续运行的旧业务不应留在这个临时时间窗口中。
4. 单次命令为 `qdc-ike-guard connect RAM_ROOT TOKEN 60 TARGET VIP`，通过控制器的 `LOGGER_READY`/`GO` 握手启动。日志、内存和 owned 子进程仍由独立运行监督器跟踪，硬期限为 80 秒加 3 秒最终终止；控制器限 90 秒。运行时低于 6144 KiB 或下降超过 3072 KiB 即中止。
5. 监督器只加载本次证书、一个 `qdc-test` 连接和一个 CHILD。验证 ESTABLISHED、INSTALLED 和预期 VIP 后，检查 `kernel-libipsec` 自动创建的唯一目标 `/32`；完成 5 次 128 字节 ping、CHILD 重协商、再 5 次 ping、读计数及正常 DELETE。不能只根据 swanctl 退出码声称握手或重协商成功，应检查日志、新 SPI、VIP、选择器和收发计数。
6. 服务器并行只读观察 `active-peers` 的实际 `id` 字段及分配地址，并核对 local-address、state、ph2。`remote-id` 不是该菜单的可靠字段。不要读取会输出密钥的 installed-sa detail；避免保存原始 IPsec debug 十六进制数据。失败时先执行恢复，不在同一暂停窗口反复尝试。

## 恢复和清理

1. 监督器先停止并回收自有客户端/CLI，检查 TUN/VIP/目标路由消失，再按专属 owner 标记清理新建凭据树；发现未知文件或无法回收进程则保留证据并转人工恢复，不递归删除或强制卸载。
2. 确认 TUN 引用为零、`/run/qdc-ike` 无残留，带连续日志普通 `rmmod tun`，继续采集 10 秒；删除本次客户端、证书、私钥及配置文件以释放 RAM。
3. 核对恢复守护和监管身份，TERM **恢复守护**；由它先 `CLOCK_RESTORED` 再 `RESUME_SENT`。不要提前手动 CONT 短信。检查原时钟加经过时间已恢复，原监管继续运行、新短信子进程和 HTTP 200 均正常。若自动超时已恢复，先读取日志，不能再发送信号给复用 PID。
4. 恢复后继续采集 30 秒，确认无客户端/测试进程、TUN 模块、VIP、目标路由或监听。移除确认由本次创建且已空的节点目录，再按已知文件列表清除本轮 RAM 目录。比较原接口、配置路由、DNS、防火墙规则和 boot/taint；单独记录动态 IPv6 缓存及计数变化。
5. 正常关闭 Mac 中继与 USB 控制器；保留电脑私有日志、公开参数及脱敏哈希，确认服务器本次身份无在线 SA。未获持久部署授权前，不设置模块启动加载，也不刷机。

这些步骤证明临时客户端能否工作；4G 直连、短信共存、长期运行和生产校时需要分别验收。
