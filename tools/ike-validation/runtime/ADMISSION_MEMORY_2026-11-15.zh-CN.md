# 临时测试工具的内存优化 · 2026-11-15

上一轮 C 版实机测试在暂停原短信后读到 12,020 KiB，未达到 12,288 KiB 准入，C 程序没有运行。本次优化集中在测试工具，保留相同准入点、三次采样和全部运行停止条件。

## 改动及影响范围

`prepare_coexist.py prepare --native-admission` 生成专用 `op=admission` 卡。主机只允许固定 RAM 路径下的 `qdc-ike-guard admit-client`，拒绝任意命令、上传字段和其他阈值；由 `exec` 替换远端 shell，避免在准入读取时保留外层 shell、awk 或 sleep 进程。守护读取真实 `/proc/meminfo`，连续三次达标、每次等待五秒才完成；20 秒报警、再三秒强制退出，电脑卡仍为 25 秒。主机还检查采样数量、顺序、阈值、间隔、同一 PID 和完成标记，不能只凭 RC=0 放行。

三轮各 30 秒日志 canary 通过后，先核对探针哈希与活进程，再回收不在运行的探针 RAM 文件。达标准入后重新上传、核对并合并探针；这部分字节已经重新计入后续暂存模型。C 版的 swap helper 和压缩候选也安排在准入后暂存。独立时钟恢复守护始终保留；不清系统缓存、不停其他服务、不把运行时基线移到 C 程序启动后。

默认仍为 12,288 KiB。此前独立授权的 11.5 MiB 例外仍要求原有参数及匹配本轮 run ID，本次没有使用。8192 KiB 启动、6144 KiB 绝对下限、3072 KiB 最大下降、30 秒/10 组、80+3 秒、1 MiB 日志上限、300 秒恢复与 180/270 秒入口/回滚年龄限制均保持原值。普通卸载和精确进程身份检查不变。

实验夹具曾因 ARM musl 的 time64 包装符号、缺失的哈希命令而失败，均保留原失败证据并修正夹具后重跑；未削弱实机校验。LTO 构建未降低守护体积，没有采用。原始实验、源码和镜像摘要保留在电脑私有 `native-c-build/admission-opt-20261115/`，没有连接外部 VPN 或发送真实短信。

## 实机执行与状态保护

1. 重新核验 USB、boot/内核/配置、原程序和监管身份、SIM、HTTP、网络、存储、内存及现场断电恢复条件。保存防火墙完整规则及去除注释/计数后的摘要。
2. 仅先暂存小守护与探针；校验摘要、自检、三轮日志 canary，确认探针退出后回收它。独立 `resume-clock ... 300` READY 后，才按精确身份暂停监管和终止原短信子进程。
3. 用新主机控制器执行原生准入卡。任何样本不足即恢复原短信；需要重传探针完成恢复后的日志观察，不进入 C 或 VPN 启动。不能省略失败阶段或自动重放未知 USB 操作。
4. 达标后，在原短信仍暂停时保存六份业务状态的大小、inode、哈希，再做只读备份并复核源文件未变。`op=backup` 只允许账户、短信、通知、通话尝试、时钟及流量六个 JSON；每份最多 256 KiB、15 秒，必须匹配新鲜大小与 SHA-256。Base64 备份文件仅存在电脑私有目录（0700/0600），每块 fsync 后确认接收；阶段日志只留元数据，不含正文、token 或密钥。原程序可能自然更新状态，不能无差别把旧快照覆盖回去。
5. 重新暂存探针；流式复制 C 候选到本轮私有 NAND 目录，完整逻辑大小加 1 MiB 保留量必须满足。只对本轮文件同步和回收缓存。验证候选、原文件、原监管和原 guardian 后生成本轮 lease/coexist 控制卡；swap `check` 和 `SWAP_READY` 均通过才进入共存。
6. 沿用原 guard 的基线与 LOGGER_READY/GO，验证 C 网页、SIM/AT 轮询及 smaps，完成固定目标的 30 秒/10 组共存。没有真实短信发送、电话或推送测试请求。
7. 结束或停止后，先停止本轮 VPN，再按原 swap 顺序停止 C、普通卸载自有绑定、核验原文件、取得时钟证明、恢复原监管。业务数据若异常，保留备份与现场并逐项确认恢复，不以 HTTP 200 代替数据健康。
8. 独立核对原 Go 进程及业务入口、数据摘要、网络、boot/taint/配置；确认无 VPN、TUN、地址/路由和挂载残留，再完成 30 秒日志观察并按白名单清理本轮文件。未知资源保留并报告恢复需求。仍不刷机、不改启动文件、不设置自启。
